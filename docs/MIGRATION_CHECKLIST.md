# Чеклист на случай переезда на другой хостинг

Этот файл — твоя подстраховка. Здесь весь список того, что нужно перенести,
если однажды понадобится уйти с poehali.dev на другой хостинг. Файл лежит
прямо в проекте, поэтому уедет вместе с кодом при подключении GitHub
(Скачать → Подключить GitHub) — не потеряется.

**Важно:** сами ЗНАЧЕНИЯ секретов ниже не показаны — платформа их не
раскрывает из соображений безопасности. Их нужно вписать вручную, когда
будешь заводить каждый секрет (значение появляется на экране только в
момент ввода). Открой этот файл, распечатай/сохрани в свой менеджер
паролей и заполни колонку «Значение» уже сейчас, не откладывая.

## 1. Секреты проекта

Всего 9 секретов. Все нужны бэкенд-функциям для работы. Заведи их на новом
хостинге под ТЕМИ ЖЕ именами (слева) — тогда код бэкенда менять не придётся.

| Имя секрета | Для чего нужен | Где взять на новом хостинге | Значение (впиши сам) |
|---|---|---|---|
| `DATABASE_URL` | Строка подключения к PostgreSQL (формат `postgresql://user:pass@host:port/db`) | Выдаётся новым провайдером БД (Neon/Supabase/Timeweb) при создании базы | _____________________ |
| `MAIN_DB_SCHEMA` | Имя схемы в базе данных (сейчас все таблицы в ней) | Обычно `public`, если создашь новую БД с нуля — узнай точное текущее значение через админку poehali перед переездом | _____________________ |
| `AWS_ACCESS_KEY_ID` | Ключ доступа к S3-хранилищу (фото из заявок) | Выдаётся новым S3-провайдером (Timeweb S3, Selectel, AWS S3) | _____________________ |
| `AWS_SECRET_ACCESS_KEY` | Секретный ключ к тому же S3-хранилищу | Там же, выдаётся в паре с ключом выше | _____________________ |
| `ADMIN_PASSWORD` | Пароль для входа в админку /admin | Придумай сам, впиши тот же, что использовался, чтобы не путать менеджеров | _____________________ |
| `VAPID_PRIVATE_KEY` | Приватный ключ для push-уведомлений (браузер/телефон) | Либо перенеси старое значение (тогда подписки клиентов останутся рабочими), либо сгенерируй новую пару — тогда всем клиентам придётся заново включить уведомления | _____________________ |
| `VAPID_PUBLIC_KEY` | Публичный ключ push-уведомлений — используется и в бэкенде, и во фронтенде | Генерируется в паре с приватным (см. выше) | _____________________ |
| `ZVONOK_CAMPAIGN_ID` | ID кампании в сервисе Zvonok.com (звонок-подтверждение телефона) | Твой личный кабинет на zvonok.com — значение не меняется при переезде хостинга | _____________________ |
| `ZVONOK_PUBLIC_KEY` | Публичный API-ключ сервиса Zvonok.com | Там же, личный кабинет zvonok.com | _____________________ |

**Как узнать текущее значение**, если не сохранил заранее:
- `MAIN_DB_SCHEMA` — можно посмотреть через инструмент просмотра базы в poehali (структура БД)
- `ZVONOK_CAMPAIGN_ID` / `ZVONOK_PUBLIC_KEY` — в личном кабинете на zvonok.com, они не привязаны к хостингу
- Остальные (`DATABASE_URL`, ключи S3, `ADMIN_PASSWORD`, VAPID) — платформа их не показывает повторно.
  Если не сохранил заранее — на новом хостинге придётся сгенерировать новые
  значения (для VAPID это значит, что клиентам нужно будет заново включить
  push-уведомления; для остального — просто прописать новые значения в код
  бэкенда там, где они читаются).

## 2. Backend-функции (Python, папка `/backend`)

Все функции уже лежат в твоём коде — их не нужно писать заново, только
залить на новый хостинг функций (Railway/Render/любой сервис с поддержкой
Python) и подключить те же секреты из раздела 1.

| Функция | Что делает |
|---|---|
| `leads-submit` | Приём новой заявки с сайта (VIN, фото, контакты), начисление бонуса за регистрацию, журнал ошибок |
| `leads-update` | Изменение заявки менеджером (статус, сумма, предоплата и т.д.) |
| `leads-admin` | Список заявок для админки /admin |
| `lead-changes` | История изменений по заявке (кто что поменял) |
| `lead-errors` | Журнал ошибок отправки заявок (для админки) |
| `garage-auth` | Вход клиента в «Гараж», пароль, подтверждение звонком, восстановление пароля |
| `garage-lookup` | Загрузка заказов клиента в «Гараже» |
| `garage-car-name` | Сохранение названия автомобиля клиента |
| `garage-mileage` | Сохранение пробега автомобиля |
| `client-notes` | Заметки менеджера по клиенту |
| `client-cashback` | Управление кэшбэком клиента |
| `push-subscribe` | Подписка клиента на push-уведомления |
| `admin-push-subscribe` | Подписка менеджера на push-уведомления в админке |
| `admin-send-push` | Отправка push-уведомлений менеджерам |
| `site-contacts` | Контакты сайта (телефон, почта, соцсети) — редактируются в админке |

После переноса каждая функция получит НОВЫЙ адрес (URL). Их нужно будет
прописать во фронтенде — сейчас все адреса собраны в `backend/func2url.json`
и продублированы прямо в коде компонентов (искать по строке
`functions.poehali.dev`).

## 3. База данных (PostgreSQL)

Все таблицы и данные (заявки, клиенты, история заказов, настройки сайта)
хранятся в одной PostgreSQL-базе. Перед переездом нужно:

1. Запросить полную выгрузку (дамп) базы данных — через поддержку poehali
   или встроенный инструмент экспорта, если он доступен в разделе «Ядро».
2. На новом хостинге (Neon, Supabase, Timeweb Cloud) создать новую базу
   PostgreSQL и восстановить её из этого дампа — у всех этих сервисов есть
   пошаговая инструкция «restore from dump» в панели управления.
3. Полученную новую строку подключения вписать в секрет `DATABASE_URL`.

---

## 4. Файлы (S3-хранилище)

Фото из заявок клиентов хранятся в S3-совместимом хранилище (не в базе
данных). При переезде:

1. Скачать все файлы из текущего хранилища (папка `leads-photos/` внутри
   бакета `files`).
2. Загрузить их в новое S3-хранилище с той же структурой папок.
3. В базе данных ссылки на фото (поля `photo_url`, `photo_urls` в таблице
   `leads`) нужно будет обновить на новые адреса — это одноразовый SQL-запрос
   массовой замены старого домена на новый.

## 5. Фронтенд (сайт, который видят посетители)

1. Скачать → Скачать код (или клонировать свой GitHub-репозиторий, если уже
   подключён — Скачать → Подключить GitHub, см. ниже).
2. Обновить адреса backend-функций в коде на новые (см. раздел 2).
3. Залить проект на любой хостинг статики: Vercel, Netlify, Cloudflare
   Pages — у всех есть режим «перетащи папку с билдом», без программирования.
4. В настройках домена у регистратора (например reg.ru) поменять DNS-записи
   на адрес нового хостинга.

## 6. Что сделать ПРЯМО СЕЙЧАС, не дожидаясь переезда

- [ ] Подключить GitHub (Скачать → Подключить GitHub) — код фронтенда и
      бэкенда будет автоматически сохраняться в твоём репозитории при
      каждом изменении.
- [ ] Заполнить колонку «Значение» в таблице секретов выше и сохранить файл
      в защищённом месте (менеджер паролей, а не просто на рабочем столе).
- [ ] Периодически (например, раз в месяц) запрашивать свежий дамп базы
      данных у поддержки poehali и хранить его отдельно.
- [ ] Проверить, что домен зарегистрирован на тебя (а не на подрядчика) —
      без доступа к DNS домена переезд невозможен в принципе.
